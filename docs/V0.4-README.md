# Aero AI Studio V0.4

기존 V0.3 코드를 확장한 PC 전용 PySide6 연구·학습 앱입니다. 동일한 폴더와 모듈을 유지하고 기존 프로젝트·시나리오·Run·모델·Python export를 계속 사용합니다. 실기체·ROS2·PX4·지도 API·LLM은 연결하지 않습니다.

## 실행

Python 3.11 이상이 필요합니다. 현재 작업 환경의 `.venv`에는 PySide6와 pytest가 설치되어 있습니다.

```powershell
# 기존 프로젝트 폴더에서
.\Start.ps1
# 다른 데이터 경로
.\Start.ps1 -Workspace 'D:\AeroWorkspace'
# 직접 실행
.\.venv\Scripts\python.exe -m aero_ai_studio
# 테스트
.\.venv\Scripts\python.exe -m pytest -q
```

새 설치 또는 ZIP을 다른 위치에 풀었을 때는 `Setup.ps1`로 venv와 editable package를 설치한 뒤 실행합니다. Python 명령을 직접 쓰는 경우:

```text
python -m venv .venv
<venv-python> -m pip install -e ".[dev]"
<venv-python> -m aero_ai_studio --workspace ./workspace
```

Linux의 venv Python은 `.venv/bin/python`입니다. Linux 및 Python 3.11 자체에서는 실행 검증하지 않았습니다. 기본 workspace는 현재 폴더의 `workspace`; Start.ps1은 프로젝트 폴더의 workspace를 사용합니다. ZIP에는 venv나 사용자 데이터가 포함되지 않습니다. `requirements-tested.txt`는 검증 환경의 패키지 버전 기록입니다.

## Train → Evaluate → Replay

1. 기존 Projects 목록에서 프로젝트를 엽니다. 앱은 최근 프로젝트를 자동 복원합니다. V0.3의 New Project 기능도 유지됩니다.
2. Scenario Lab에서 저장된 scenario를 편집하거나 Load JSON을 사용합니다. 0.3 파일은 메모리에서 0.4로 변환되며 Save를 눌러야 덮어씁니다.
3. Grid preset 10/20/30/Custom, click tool Wall/Obstacle/Agent/Goal/Moving/Danger/Slow/Erase를 선택하고 지도를 클릭합니다. Moving은 Horizontal/Vertical/Random을 지원합니다. 상단 **Save scenario + preview**로 적용합니다.
4. Generate Random Scenario는 difficulty/density/moving count/danger count/seed를 사용합니다. 동일 seed와 설정은 같은 scenario를 생성합니다. 정적 목표 경로를 확보하며 너무 많은 객체는 오류로 거부합니다. 생성 결과는 먼저 draft이고 Save로 적용합니다.
5. AI Training에서 Train합니다. Fast는 grid 신호를 보내지 않고, Visual은 선택한 Episode마다 step을 표시합니다. Episode/Step/Action/Reward/Epsilon과 reward/success 그래프를 제공합니다. Visual Mode는 표시를 위해 step당 20ms 대기하므로 Fast보다 느립니다.
6. Checkpoint interval마다 자동 저장합니다. **Save Checkpoint**는 현재 Episode 끝에 저장을 요청합니다. Stop/창 닫기도 현재 Episode를 마치고 최종 checkpoint를 저장합니다.
7. 앱을 다시 열고 **Resume Training**에서 checkpoint와 전체 episode 목표를 선택합니다. N회를 완료했다면 N+1회부터 진행합니다. 원본 Run은 보존하고 이력을 복사한 후속 Run을 만듭니다.
8. Models에서 Run을 이름으로 저장합니다. 같은 이름으로 저장하면 v1/v2/v3가 증가합니다. 모델 row에서 Evaluate 버튼을 누르면 Evaluation으로 이동합니다.
9. Evaluation은 **epsilon=0, Q-table 업데이트 없음**입니다. Model scenario snapshot 또는 현재 saved scenario, Episodes/Max Steps/Seed를 지정합니다. 학습 metrics와 별도의 evaluation.json 및 Episode 파일을 저장합니다.
10. 평가 결과의 **Replay selected evaluation** 또는 Replay의 `EVALUATION` 항목에서 평가도 재생합니다. All/Success/Failure/Collision/Timeout/Dynamic/Danger 필터, Best/Shortest/Highest Reward를 제공합니다.
11. Brain Map V2는 pre-update Q-value, 선택 행동, Exploration/Exploitation, epsilon, 상태/결과, mission/주변 객체, Valid/Invalid 및 기하학적 risk를 표시합니다. Timeline을 클릭하면 Replay Grid와 Brain Map이 같은 step으로 이동합니다.
12. 실패 Episode에는 로그 규칙 기반 분석이 자동 표시됩니다. terminal step·Q-values·직전 행동·반복 상태·목표 거리 정체를 근거로 가능한 원인을 설명합니다. 숨겨진 사고를 추정하거나 LLM 결과를 생성하지 않습니다.
13. Training Comparison에서 Ctrl/Shift로 최대 5개 Run을 선택해 설정·reward/success 곡선·평균 steps·연결 모델을 비교합니다. Models는 Duplicate/Rename/Notes/Delete를 지원합니다. 삭제는 기본 No 확인창을 거칩니다.

## 학습·평가 지표

Training success는 탐험을 포함한 누적 성공률입니다. Evaluation success는 고정된 모델의 greedy Episode 성공률입니다. Greedy 동점만 seed 기반 무작위 선택하며 그 외 탐험은 없습니다. 두 수치를 혼용하지 않습니다. Dashboard의 기존 평균 성공률 카드는 Training 기준을 유지합니다.

평가 결과: Success/Failure Rate, Average Reward/Steps, Collision/Timeout Count, Shortest Path Ratio, Path Efficiency. 두 경로 지표는 성공 Episode에 대해서만 평균합니다.

- Shortest Path Ratio = 정적 최적 경로 거리 / 실제 이동 거리 (1에 가까울수록 좋음)
- Path Efficiency = 실제 이동 거리 / 정적 최적 경로 거리 (1에 가까울수록 좋음)
- 성공이 없으면 `null`/N/A입니다. 동적 타이밍 및 Slow 비용을 반영한 최적 제어 지표가 아닙니다.

기본 20×20 환경: 학습 1,000회 전체 성공 52.2%, 마지막100회 96%; 별도 평가100회 성공100%, 평균38 steps. 매 Episode 장애물 위치를 바꾼 환경: 학습/평가 성공0%. Basic (x,y)만 사용하는 정책의 환경 변화 일반화 한계를 그대로 기록합니다. 실기체나 일반 비행 성능 지표가 아닙니다.

## 데이터

```text
workspace/
  logs/app.log                 # 회전 로그 2 MB × 본체 + 백업3개
  projects/project_<id>/
    project.json
    scenarios/scenario.json    # schema_version 0.4
    runs/run_<id>/
      run.json
      metrics.json
      q_table.json
      episodes/episode_0001.json
      checkpoints/episode_000100/checkpoint.json
    evaluations/eval_<id>/
      evaluation.json
      metrics.json
      episodes/episode_0001.json
    models/model_<id>/
      metadata.json            # version/parent/notes/evaluation references
      q_table.json
    exports/model_<id>/
      policy.py
      metadata.json
      q_table.json
```

JSON은 staging write → flush/fsync → parse validation → atomic replace입니다. Checkpoint는 단일 payload를 검증한 디렉터리를 rename해 commit합니다. 부분 `.pending_*` 폴더는 Resume 목록에서 제외됩니다. 앱 로그는 start/open/load/training/checkpoint/end/error를 기록합니다.

## 구조와 호환성

`projects/scenario/simulation/agents/training/explainability/replay/models/deploy` 기존 모듈을 유지했습니다. 신규 `evaluation`은 optimizer와 분리됩니다. `ui/research_panels.py`는 기존 MainWindow의 추가 패널을 구성하며 별도 앱이나 중복 MainWindow를 만들지 않습니다.

`SimulationEnvironment`는 reset/step/observation/state/metrics/render/close와 capabilities를 확정합니다. 기존 TrainingEnvironment는 alias로 유지합니다. Trainer/Evaluator의 factory 주입으로 환경을 교체합니다. [상세 계약](docs/SimulationContract.md), [V0.5 Gazebo 계획](docs/GazeboIntegration.md)을 참고하세요.

## 현재 제한사항 / 기술 부채

- Q-agent와 export는 **Basic 위치(x,y)**를 계속 사용합니다. ObservationSpec와 Extended observation 조회는 제공하지만 Extended 상태를 학습·export에 사용하지 않습니다. 동적·랜덤 환경에서 낮은 성능은 예상 가능한 한계입니다.
- 2D 정적/이동 점유 모델입니다. Dynamic 충돌은 이전/새 cell의 보수적 검사입니다. Danger는 -50 terminal, Slow는 step reward -3 추가이며 물리 속도 변화는 없습니다. 실제 센서·날씨·비행 동역학은 없습니다.
- 실행은 Synthetic의 obstacle avoidance/navigation만 지원합니다. Korea/Hybrid, Tracking/Landing/Reconnaissance, Paper/Video 분석, 다른 export는 기존 설정/구조 단계입니다.
- UI 편집은 정사각형, Core는 직사각형도 지원합니다. 프로젝트당 active scenario 하나이며 Run/Model/Evaluation은 자체 snapshot을 보관합니다.
- 자동 생성은 정적 안전 경로를 보존하지만 이동 장애물이 그 경로를 통과할 수 있습니다. 객체 수가 작은 grid의 가용 cell을 넘으면 줄여야 합니다.
- risk는 확률이 아닌 기하학적 휴리스틱입니다. Loop 검출은 최대8-step 패턴의 3회 반복으로, 전역적 정책 검증이나 원인 증명이 아닙니다.
- 정상 중지는 Episode 종료까지 기다립니다. 강제 종료 후 Resume은 마지막 committed checkpoint로 돌아갑니다. checkpoint 이후 Episode는 복구되지 않습니다. 후속 Run의 Replay 이력을 복사하려면 원본 Run 로그가 필요합니다.
- checkpoint의 source_run은 절대 경로입니다. workspace를 다른 컴퓨터/경로로 옮겼을 때 자동 경로 재배치는 후속 과제입니다. 여러 앱의 동시 쓰기는 지원하지 않습니다.
- JSON/중복 checkpoint Q-table/Replay prefix 복사는 대규모 학습에서 저장 비용이 큽니다. 압축·DB·retention·Q-table cache가 후속 과제입니다. freeze한 모델은 평가 때 변경하지 않지만 metadata에는 평가 참조를 추가합니다.
- 실패한/일부 취소 평가 지표는 완료된 Episode만 집계합니다. 모델 평가 이력에는 completed 결과만 연결합니다. 모델 삭제 후 평가 로그는 남고 링크의 모델 파일은 없어질 수 있습니다.
- Python 3.14.3 / Windows Qt offscreen 자동 검증입니다. native Windows 사용자 수동 조작, Linux, installer EXE, 실제 강제 프로세스 kill은 검증하지 않았습니다.
