# Aero AI Studio V0.5

기존 V0.4 프로젝트를 같은 폴더에서 확장했습니다. Basic Q-Learning·기존 프로젝트·시나리오·모델·체크포인트·Replay를 유지하며, 센서 관측과 DQN 및 Gazebo World launch를 추가했습니다.

## 실행

현재 프로젝트의 `.venv`에는 PySide6·pytest·CPU PyTorch·NumPy가 설치되어 있습니다.

```powershell
.\Start.ps1
# 다른 workspace
.\Start.ps1 -Workspace 'D:\AeroWorkspace'
# 직접 실행 / 테스트
.\.venv\Scripts\python.exe -m aero_ai_studio
.\.venv\Scripts\python.exe -m pytest -q
```

다른 위치에 소스 ZIP을 풀거나 새 환경을 구성할 때는 Python3.11 이상을 설치한 뒤:

```powershell
.\Setup.ps1                 # 기존 Q-learning 기능
.\Setup.ps1 -IncludeDqn     # 선택: PyTorch/NumPy 포함
```

또는 venv를 만들고 `python -m pip install -e ".[dev,dqn]"`을 실행합니다. DQN은 선택 의존성이며 torch가 없으면 UI에서 선택을 비활성화합니다. GridWorld/Q-learning은 계속 실행됩니다. Linux에서는 `.venv/bin/python`을 사용합니다. 실제 검증은 Windows/Python3.14.3/Qt offscreen/CPU Torch2.15.0에서 수행했습니다.

## 사용 흐름

1. 기존 Projects 목록에서 프로젝트를 엽니다. V0.4 New Project 기능도 유지합니다.
2. Scenario Lab에서 Grid와 객체를 편집·생성하고 Save합니다. Scenario observation에 BASIC/LOCAL/SENSOR/FULL_DEBUG를 준비했으며 FULL_DEBUG는 정책 학습에 사용할 수 없습니다.
3. AI Training에서 Simulator=GridWorld, Algorithm=Q-Learning 또는 DQN, Observation=basic/local/sensor를 고릅니다. local 크기는3×3/5×5/7×7입니다.
4. Q-learning+basic은 기존 위치 상태를 사용합니다. Q-learning+local/sensor는 Compact encoder를 사용합니다. DQN은 local/sensor를22차원 입력으로 변환합니다.
5. DQN 선택 시 학습률0.001·Sensor·epsilon end0.05가 기본 적용됩니다. Advanced settings에서 Batch Size/Replay Buffer/Target Update/Epsilon End를 설정합니다. Episodes/Gamma/Start Epsilon/Decay/Max Steps는 공통입니다.
6. Start/Stop/Checkpoint/Resume은 상단에 고정됩니다. Fast/Visual 및 Episode 표시 빈도와 자동 checkpoint는 기존과 같습니다. DQN checkpoint는 weights 외에 optimizer/target/buffer/RNG도 저장합니다.
7. Models에서 Run을 저장하고 Evaluate합니다. 모델별 observation/encoder를 자동 복원하며 Evaluation은 epsilon0, learn 호출 없음, 학습과 겹치지 않는 reset seed를 사용합니다.
8. Evaluation의 Generalization Test는 새로운 seed로 기준 시나리오를 평가하고 Random Obstacles/Moving Obstacles/Different Difficulty 조건으로 다시 평가합니다. 기준 성공률·Unseen 성공률·Gap을 저장합니다. 기준은 학습 rollout 재사용이 아니라 새 평가입니다.
9. Replay의 What AI Saw 탭 또는 Observation Debug에서 전체 환경과 실제 정책 Observation을 나란히 봅니다. Brain Map V3에는 Q-table 또는 network output Q-values, 탐험/활용, 입력 feature, 행동과 결과를 표시합니다. Timeline/Replay/Grid/Observation은 같은 step을 공유합니다.
10. Training Comparison에서 Q Basic/Q Sensor/DQN Sensor의 학습·평가 성공률, 평균 reward/steps, 충돌/timeout 비율, 학습 시간, 저장 크기를 비교합니다. 평가가 없는 모델은 N/A입니다.

## Gazebo 흐름

Scenario → Export to Gazebo → SDF/metadata → Launch Gazebo. Diagnostics에서 환경 상태와 Launch/Stop을 확인합니다. Gazebo가 없으면 Unavailable을 표시하고 앱은 계속 실행됩니다. GUI가 실제 생성한3D world를 표시하는지 확인하는 것은 Ubuntu 실행 환경에서 해야 합니다.

V0.5의 Gazebo는 **실제 프로세스 launch/stop과 SDF 생성** 범위입니다. 센서/행동 기반3D 학습은 V0.6이며 reset/step은 명시적으로 미구현 오류를 반환합니다. Moving Object는 SDF에서 정적인 주황색 proxy입니다. 실제3D 움직임을 구현했다고 보고하지 않습니다. ROS2/ros_gz는 선택적 진단·bridge abstraction이며 실기체나 PX4에 연결하지 않습니다.

## 실제 결과

| 조건 | 학습 Episode | 평가 Episode | 평가 성공률 | 충돌 / Timeout |
|---|---:|---:|---:|---:|
| 기존 Basic·고정20×20 |1000|100|100%|0 / 0|
| Basic·매회 랜덤장애물10% |3000|200|0%|19 / 181|
| Compact Sensor·동일 랜덤계열 |3000|200|64.5%|0 / 71|
| DQN Sensor·동일 랜덤계열 |1000|200|74.5%|51 / 0|

학습 reset seeds는43…3042(Q) 또는43…1042(DQN), 평가 seeds는10043…10242로 겹치지 않습니다. Basic/Sensor는 동일 예산·환경계열 비교입니다. DQN은 학습 예산과 설정이 다르므로 알고리즘 순위로 일반화하지 않습니다. 기존 고정환경은 평균38 steps를 유지했습니다.

별도의 **더 어려운 조건+이동장애물** Generalization50회 시험에서는 Compact의 기준66%→Unseen0%(Gap66%p)였습니다. 랜덤 정적 장애물 개선이 모든 동적 환경으로 일반화됐다는 의미가 아닙니다. DQN 평가51회 충돌도 남아 있습니다. 자세한 측정은 VALIDATION.md와 validation/v05/performance_v05.json에 있습니다.

## 데이터·설계

기존 workspace/runs/episodes/checkpoints/models/evaluations 구조를 유지합니다. Q 모델은 q_table.json, DQN은 model.pt와 metadata.json입니다. Episode에는 실제 observation/next_observation/agent_decision/algorithm을 추가했습니다. 기존 로그는 Observation not recorded로 표시합니다. ScenarioSpec은 호환 schema0.4를 유지하고 Observation payload는0.5입니다.

JSON/모델은 staging 검증 후 atomic replace합니다. Checkpoint는 디렉터리 단위 commit입니다. 모델 metadata의 학습 지표와 별도 평가 지표를 구분합니다. Application 로그는 기존 RotatingFileHandler를 사용합니다. Prefix 이력 복사를 위한 원본 Run 경로 보존 조건도 유지합니다.

## 알려진 한계

- Sensor는 이상적인2D range/proximity 측정이며 실제 카메라/LiDAR/잡음/가림/지연 모델이 아닙니다. 상대 motion은 이전 step의 거리 변화입니다.
- Compact는 유한한 feature 상태를 공유하므로 우회 진행 상태·속도를 완전히 관측하지 못합니다. Loop/Timeout 및 분포 변화 실패가 남습니다.
- DQN은 기본 MLP/CPU 학습입니다. Image/continuous action/GPU UI/recurrent policy/보장된 충돌회피는 없습니다. Q값은 확률이나 숨겨진 사고가 아닙니다.
- DQN 저장 크기는 optimizer/buffer를 포함합니다. Compact/DQN Python export는 matching package/Observation schema가 필요하며 Basic export만 standalone입니다.
- Evaluation seed overlap은 provenance가 있는 모델에 대해 검사합니다. 기존 모델에 학습 설정을 복구할 수 없으면 사후 seed 검증은 제한됩니다.
- Generalization은 실패·취소된 결과도 숨기지 않습니다. Gap은 기준 새 평가와 새 조건 평가의 차이이며 통계적 유의성이나 신뢰구간을 제공하지 않습니다.
- Gazebo/Harmonic/Ubuntu 실제 launch·렌더링·물리 센서는 현재 Windows에서 검증하지 못했습니다. 생성된 XML을 실제 libsdformat으로 검증한 결과로 혼동하지 않습니다.
- native Windows 수동 E2E·Linux·실제 프로세스 강제 종료·여러 앱 동시쓰기·대용량 로그 DB 전환은 후속 과제입니다. Paper/Video/Korea UI와 Adapter는 기존 범위로 유지합니다.
