# Aero AI Studio V0.3

항공·방산 연구를 중심으로 드론·로봇·게임 AI로 확장하기 위한 **PC 전용 PySide6 데스크톱 앱**입니다. 기존 F450 프로젝트와 독립적이며 실기체를 연결하지 않습니다.

## 실행

Python 3.11 이상이 필요합니다. Windows PowerShell에서 프로젝트 폴더로 이동합니다.

```powershell
.\Setup.ps1
.\Start.ps1
# 다른 데이터 폴더
.\Start.ps1 -Workspace 'D:\AeroWorkspace'
```

PowerShell 스크립트 실행이 제한된 경우 Python 명령으로 직접 실행할 수 있습니다. 이 작업에서 생성한 `.venv`에는 의존성을 설치했습니다.

```powershell
.\.venv\Scripts\python.exe -m aero_ai_studio
.\.venv\Scripts\python.exe -m pytest -q
```

새 컴퓨터에서는 다음 방식도 가능합니다.

```text
python -m venv .venv
<venv-python> -m pip install -e ".[dev]"
<venv-python> -m aero_ai_studio --workspace ./workspace
```

Linux에서는 `<venv-python>`을 `.venv/bin/python`으로 사용합니다. Linux 실제 실행은 아직 검증하지 않았습니다. 기본 workspace는 실행 시 현재 폴더의 `workspace`; Start.ps1은 프로젝트 폴더의 `workspace`로 고정합니다.

## 실제 사용 흐름

1. Projects에서 이름·설명·AI 유형·목표를 입력하고 **New Project**를 누릅니다.
2. Scenario Lab에서 환경·미션·날씨·센서·랜덤화를 설정합니다. 실행에는 `synthetic`과 `obstacle_avoidance` 또는 `navigation`을 선택합니다. 기본 20×20 창고 시나리오에는 벽과 우회 경로가 있습니다.
3. 오브젝트 유형과 좌표로 **Add**하거나 `type,x,y` 형식의 텍스트 행을 편집하고 **Save scenario + preview**를 누릅니다. JSON 수동 편집은 필요하지 않습니다. 시작점은 (0,0), 목표는 우하단입니다.
4. AI Training에서 기본 1,000회 또는 500회로 **Start Training**을 누릅니다. 별도 Qt 스레드에서 학습하며 Episode/Reward/Steps/Success/Collision/Epsilon과 그래프를 표시합니다.
5. Replay에서 Run과 Episode를 선택합니다. `collision`, `timeout`, `failed` 필터로 실패를 찾고 재생·일시정지·이전·다음·1/2/4배속·슬라이더를 사용합니다.
6. Grid, 행동, reward, Brain Map은 같은 step 로그를 참조합니다. AI Brain Map 페이지에도 선택한 episode/step이 유지됩니다.
7. Models에서 **Save selected Replay run as Model**을 누르고 이름을 입력합니다. Deploy에서 모델을 고른 뒤 Local Python으로 export합니다. 내보낸 폴더에 `policy.py`, `q_table.json`, `metadata.json`이 생성됩니다.
8. 앱을 다시 실행하면 최근 프로젝트를 열고 저장된 시나리오·Run·모델을 복원합니다. 다른 프로젝트도 목록에서 열 수 있습니다.

학습 중 프로젝트 변경과 시나리오 저장은 잠깁니다. 중지 요청이나 창 닫기는 worker에 취소 신호를 보내고 부분 로그와 Q-table을 저장한 뒤 종료합니다.

## 데이터와 판단 근거

```text
workspace/projects/project_<id>/
  project.json
  scenarios/scenario.json
  runs/run_<id>/
    run.json                 # 설정, scenario snapshot, 상태, 집계
    metrics.json             # Episode 요약
    q_table.json
    episodes/episode_0001.json
  models/model_<id>/
    metadata.json
    q_table.json
  exports/model_<id>/
    policy.py
    metadata.json
    q_table.json
  replays/                   # 예약; Replay는 원본 run 로그를 직접 읽음
  paper_reference.json
  video_reference.json
```

Brain Map은 숨겨진 사고를 재현하지 않습니다. Q-value는 확률이 아니며 행동 선택 전의 학습 추정값입니다. epsilon 탐험 시 최고 Q-value와 다른 행동이 선택될 수 있고 동점은 무작위로 선택합니다. 로그에는 이 구분과 실제 새 상태를 저장합니다. Grid의 파란 A는 행동 이전, 노란 테두리는 결과 위치입니다. 충돌 시 위치는 유지됩니다.

성공률은 **탐험을 포함하는 학습 Episode의 누적 비율**입니다. 모델 메타데이터에도 동일하게 명시합니다. 검증 테스트는 저장된 정책으로 greedy 목표 도달을 별도로 확인합니다. 일반화 성능이나 실기체 성능을 뜻하지 않습니다.

## 설계

- `core` JSON 원자적 교체 / `projects` 로컬 프로젝트 저장
- `scenario` dataclass와 검증 / `simulation` TrainingEnvironment Protocol과 GridWorld
- `agents` Q-table / `training` UI 없는 Trainer·Logger
- `explainability` BrainEvent / `replay` UI 없는 ReplayEngine
- `models`, `deploy` 모델 저장과 독립 Python export
- `paper`, `video`, `adapters` 확장용 구조 / `ui` PySide6와 커스텀 QPainter Grid·그래프
- Trainer는 environment factory를 주입받습니다. Qt 의존성은 app/ui에 한정됩니다.
- UTF-8 JSON과 UUID 경로를 사용합니다. 동일 이름의 프로젝트와 모델을 별도로 보존합니다. 로그는 각 Episode 직후 저장하고 지표·Q-table·최종 상태는 run 완료/취소 시 저장합니다.

## 제한사항과 기술 부채

- 2D 정적 점유 Grid이며 카메라/LiDAR/GPS의 실제 센서 모델, 비행 동역학, 날씨·조명·속도·센서 잡음·GPS 오차 효과가 없습니다. 해당 설정은 **metadata only**로 표시합니다. 오브젝트 유형 모두 한 셀 장애물입니다.
- 실행 미션은 장애물 회피/정적 목표 Navigation입니다. Tracking/Landing/Reconnaissance와 Korea/Hybrid는 설정 저장만 지원하고 학습 시작 시 명확히 거부합니다.
- 위치 `(x,y)`만 Q-table 상태로 사용합니다. 장애물 위치/개수 랜덤화는 환경 변화 시험용이며 부분 관측 aliasing으로 정책 품질이 낮아질 수 있습니다. 상태에 지역 점유·목표를 포함하는 확장이 필요합니다.
- UI 편집기는 정사각형·고정 시작/목표만 지원합니다. Core는 직사각형과 다른 시작/목표를 지원합니다. 프로젝트당 활성 scenario 파일 하나를 사용하며 run에는 독립 snapshot을 보존합니다.
- JSON Episode 로그는 이해하기 쉽지만 대규모 학습에는 용량·I/O 부담이 큽니다. 요약/선택 step 스트리밍, SQLite/압축 저장, 보존 정책이 후속 과제입니다.
- 정상 취소는 부분 run을 보존합니다. 강제 프로세스 종료에서는 run이 `running`으로 남을 수 있으며 metrics/Q-table 복구는 미구현입니다.
- 기본 성공률은 학습 성과이며 별도의 UI 평가 워크플로는 없습니다. 고정 seed 학습·greedy 검증 테스트만 제공됩니다.
- 학습 재개, checkpoint, 모델 버전 자동 증가, 여러 앱의 동시 workspace 쓰기, 스키마 마이그레이션, 손상된 파일 자동 격리는 미구현입니다.
- 설치형 EXE, GPU·Deep RL, 실기체 제어, LLM/PDF/Video 실제 분석은 제공하지 않습니다.

## V0.4 Gazebo 연결

1. `TrainingEnvironment`를 만족하는 GazeboAdapter와 lifecycle/reset/timeout/close를 구현합니다. Trainer의 `environment_factory`로 교체합니다.
2. 현재 위치 tuple 및 네 방향 행동을 일반 observation/action schema로 확장합니다. 센서 timestamp, 단위, 좌표계, simulator seed와 버전을 명시합니다.
3. 센서 기반 상태 인코더와 Agent Protocol을 도입하고 Q-table 모델의 환경 호환성 검증을 추가합니다. 현재 Q-table을 3D 비행 정책으로 직접 사용하지 않습니다.
4. 비동기 관측·시뮬레이터 step 및 취소를 처리하고 연결 실패/시간 초과/재연결을 검증합니다.
5. BrainEvent와 Replay snapshot schema에 3D pose·감지·위험 평가의 실제 측정값을 추가합니다. Grid renderer와 3D renderer를 별도 Adapter로 분리합니다.
6. UI 독립 평가 runner로 greedy 정책·고정 seed suite·학습/평가 분리·실패 비교를 구현합니다. ROS2/PX4 실기체 연동은 별도 단계입니다.

Phase별 파일·구현·검증·잔여 사항은 `PHASE_LOG.md`, 실제 실행 검증은 `VALIDATION.md`에 기록합니다.
